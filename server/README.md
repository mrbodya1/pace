# Домашний сервер PACE: подготовка альфы

Подготовлена схема аккаунтов для PocketBase **0.41.1**. Сервер ещё нужно установить и проверить. Кнопки входа Flutter пока не подключены; тренировки и XP остаются в `pace_local_data` на телефоне.

## Локальный запуск на Windows

1. Скачайте официальный архив Windows x64 версии 0.41.1 со страницы [PocketBase](https://pocketbase.io/docs/). Распакуйте `pocketbase.exe` в `server/runtime`.
2. Из папки проекта запустите `powershell -ExecutionPolicy Bypass -File .\server\start.ps1`.
3. Откройте локальную ссылку установки из окна сервера и создайте администратора. Не присылайте его пароль в чат и не используйте его для тестировщиков.
4. Панель: http://127.0.0.1:8090/_/ . Проверка доступности: http://127.0.0.1:8090/api/health . Остановка: Ctrl+C.

Миграция применяется при запуске автоматически. Создаётся отдельная коллекция `pace_users`, стандартные коллекции не меняются. Изменения коллекции и настроек проходят в транзакции миграции. Скрипт не открывает порты роутера и не запускает публичный туннель.

## Правила аккаунтов

- Регистрация по email и паролю от 12 символов; необязательное имя до 40 символов.
- Участник читает и изменяет только свой аккаунт. Список тоже возвращает только собственную запись.
- Нельзя самостоятельно задавать `verified` и `emailVisibility`. Удаление через клиентский API и управление чужими аккаунтами закрыты.
- Включается встроенное ограничение частоты запросов с существующими правилами PocketBase.
- OAuth, одноразовые коды и почтовые уведомления о входе пока выключены.

До настройки SMTP альфа допускает вход без подтверждения адреса. Не показывать «Почта подтверждена» и не обещать восстановление пароля письмом. Создание аккаунта само по себе не выполняет вход: клиент затем вызывает `auth-with-password`.

## Проверка перед подключением приложения

`powershell -ExecutionPolicy Bypass -File .\server\test.ps1`

Проверка запускает отдельный сервер на свободном локальном порту с временной базой, создаёт два тестовых аккаунта, проверяет регистрацию, вход, обновление токена и запрет доступа к чужим записям. Рабочая `pb_data` не используется. Временный процесс останавливается и его база удаляется. Нужен установленный `runtime/pocketbase.exe`; без него проверка завершается сообщением, а не скачивает программу.

## Доступ через интернет — следующий шаг

Нужен HTTPS-туннель к домашнему ПК. До его открытия необходимо закрыть извне панель, установку и административные API; проверить реальный IP посетителя и ограничения запросов за прокси. Адрес приложения должен быть HTTPS. Сейчас сервер слушает только `127.0.0.1`.

VK, Яндекс и Mail требуют отдельной настройки приложений провайдеров. Их ключи не добавлять в Flutter или Git. Настройка этих входов не входит в эту миграцию.

## Хранение и обновление

`pb_data` содержит личные данные и секреты; она исключена из Git вместе с `runtime`. Для резервной копии остановите сервер и скопируйте всю `pb_data` в закрытое место. Миграция не содержит автоматического отката с удалением аккаунтов: восстановление выполнять из резервной копии. Не редактировать уже применённую миграцию, добавлять новую.

Домашний ПК, сервер и будущий туннель должны работать одновременно. Сон компьютера прервёт доступ. PocketBase — стороннее ПО на вашем ПК, а не российское облако.
