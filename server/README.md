# Домашний сервер PACE: подготовка альфы

Настроены аккаунты, серверный профиль и синхронизация прогресса для PocketBase **0.41.1**. Тренировки сохраняются в SQLite устройства, затем отправляются по одной в V2 API; показатели и телеметрия хранятся отдельно. История передаётся страницами, GPS/пульс — при открытии подробностей. Текущая архитектура и переход: [хранилище V2](../docs/storage-v2-plan.md). [Старый протокол](../docs/account-progress.md) оставлен как историческое описание и закрыт кодом426.

## Локальный запуск на Windows

1. Скачайте официальный архив Windows x64 версии 0.41.1 со страницы [PocketBase](https://pocketbase.io/docs/). Распакуйте `pocketbase.exe` в `server/runtime`.
2. Из папки проекта запустите `powershell -ExecutionPolicy Bypass -File .\server\start.ps1`.
3. Откройте локальную ссылку установки из окна сервера и создайте администратора. Не присылайте его пароль в чат и не используйте его для тестировщиков.
4. Панель: http://127.0.0.1:8090/_/ . Проверка доступности: http://127.0.0.1:8090/api/health . Остановка: Ctrl+C.

Миграции применяются при запуске автоматически. **Миграция1794477600 создаёт V2 и удаляет прежние тренировки/производный прогресс и результаты зачётов по согласованному чистому старту. Перед обновлением существующего сервера необходима остановленная проверенная резервная копия.** Аккаунты, профили и клубы сохраняются. `start.ps1` явно подключает `pb_hooks` и запрещает тестовый флаг старого API. Изменения проходят в транзакции миграции. Скрипт не открывает порты роутера и не запускает публичный туннель.

## Правила аккаунтов

- Регистрация по email и паролю от 12 символов; необязательное имя до 40 символов.
- Участник читает и изменяет только свой аккаунт. Список тоже возвращает только собственную запись.
- Нельзя самостоятельно задавать `verified` и `emailVisibility`. Удаление через клиентский API и управление чужими аккаунтами закрыты.
- Включается встроенное ограничение частоты запросов с существующими правилами PocketBase.
- OAuth, одноразовые коды и почтовые уведомления о входе пока выключены.

До настройки SMTP альфа допускает вход без подтверждения адреса. Не показывать «Почта подтверждена» и не обещать восстановление пароля письмом. Создание аккаунта само по себе не выполняет вход: клиент затем вызывает `auth-with-password`.

## Проверка перед подключением приложения

`powershell -ExecutionPolicy Bypass -File .\server\test.ps1`

Проверка запускает отдельный сервер на свободном локальном порту с временной базой, создаёт два тестовых аккаунта, проверяет регистрацию, вход, обновление токена и запрет доступа к чужим записям. Рабочая `pb_data` не используется. Временный процесс останавливается и его база удаляется. Нужен установленный `runtime/pocketbase.exe`; без него проверка завершается сообщением, а не скачивает программу.

## Доступ через интернет

Публичный HTTPS API: https://bodya1-pc.tail3c1c24.ts.net . Телефону и эмулятору Tailscale не нужен. Funnel направлен на защищённый Caddy 127.0.0.1:8091; PocketBase остаётся на 127.0.0.1:8090, административные маршруты снаружи закрыты. Проверены TLS, публичный relay и ограничения запросов с защитой от поддельного IP. Подробности: [HTTPS-доступ](../docs/https-access.md).

VK, Яндекс и Mail требуют отдельной настройки приложений провайдеров. Их ключи не добавлять в Flutter или Git. Настройка этих входов не входит в эту миграцию.

## Хранение и обновление

`pb_data` содержит личные данные и секреты; она исключена из Git вместе с `runtime`. Для резервной копии остановите сервер и скопируйте всю `pb_data` в закрытое место. Миграция не содержит автоматического отката с удалением аккаунтов: восстановление выполнять из резервной копии. Не редактировать уже применённую миграцию, добавлять новую.

Домашний ПК, сервер и будущий туннель должны работать одновременно. Сон компьютера прервёт доступ. PocketBase — стороннее ПО на вашем ПК, а не российское облако.

Справка: [миграции](https://pocketbase.io/docs/js-migrations/), [правила доступа](https://pocketbase.io/docs/api-rules-and-filters/), [эксплуатация](https://pocketbase.io/docs/going-to-production/).


## Работающий HTTPS-шлюз — 12 ноября 2026

Выбран Tailscale Funnel, не Tuna. Конфигурация server/gateway/Caddyfile пропускает только API PACE и слушает 127.0.0.1:8091; административные маршруты отклоняются. Установлены отдельные задачи PACE-PocketBase и PACE-API-Gateway после явного подтверждения пользователя. Миграция доверенного IP применена после свежей закрытой копии базы; ограничения запросов сохранены. Подробности/проверки/откат: [HTTPS-доступ](../docs/https-access.md).

Публичный Funnel включён после отдельного согласия пользователя и его подтверждения в Tailscale: https://bodya1-pc.tail3c1c24.ts.net → loopback gateway 8091. Через публичный relay проверены валидный TLS, health200, блокировка admin404 и защита auth rate limit от поддельного IP. Клиентские запуски — run-remote.ps1 и run-web-remote.ps1; смена API URL требует повторного входа и предварительной синхронизации старой локальной очереди.
