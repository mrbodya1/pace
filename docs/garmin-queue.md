# Garmin: подтверждение и освобождение временной очереди

12 ноября2026,22:23 Asia/Yekaterinburg. По прямой команде пользователя миграция и hooks применены на рабочем сервере после проверенной остановленной копии и репетиции на её дубликате. Перезапущен только PocketBase. APK не собирался; пользователь отдельно разрешил публикацию этого этапа в GitHub.

## Поведение

1. Коллектор получает только новые Garmin-тренировки после существующего cutoff и складывает FIT-показатели/GPS/HR во временный inbox. Привязка, ключ, cutoff и режим обновления при открытии приложения сохраняются.
2. PACE сохраняет тренировку локально в SQLite и отправляет её через V2. Пока сервер не зафиксировал полный commit, исходный пакет остаётся в inbox.
3. В той же транзакции сервер сравнивает пакет с привязанной приватной очередью: внешний ID, SHA256 исходного FIT, начало/окончание, спорт, дистанцию, длительность и набор. Все загруженные route/timedRoute/heartRateSamples должны совпасть с исходными отсчётами; эквивалентные UTC timestamp и отсутствующий segment0 нормализуются. Пропущенный или изменённый GPS/пульс отклоняет commit без квитанции и без частично сохранённого прогресса.
4. После commit создаётся закрытая квитанция pace_garmin_receipts, scoped по owner+epoch+cutoff+externalId. Она остаётся после очистки очереди. Повтор HTTP/потеря ответа не удваивают тренировку, XP или квитанцию.
5. После успешной синхронизации клиент вызывает action=ackGarmin на существующем POST /api/pace/v2/workouts. Дополнительного публичного маршрута и изменений Caddy не требуется. Для чужого/непривязанного аккаунта действие ничего не очищает. Отказ обслуживания очереди не отменяет уже успешную синхронизацию.
6. Пока физический файл ещё не очищен, GET Garmin скрывает пакеты с точной подтверждённой парой ID/FIT-hash. Для тренировок, сохранённых до этой миграции, обслуживание проверяет полную серверную телеметрию и создаёт отсутствующие квитанции; совпадения одного ID недостаточно.
7. Физический inbox изменяет только Python-коллектор под тем же collector.lock, что и обычный импорт. Режим --prune-only читает квитанции из PocketBase SQLite строго mode=ro, проверяет ожидаемого владельца и атомарно заменяет inbox. Garmin-сеть и DPAPIключ для обслуживания не используются. Занятый worker возвращает busy; очередь остаётся до следующей синхронизации/обновления. Пустая очередь или отсутствие подтверждённых пакетов не запускают лишний процесс.

## Восстановление и объём

- Квитанция хранится на сервере до удаления пакета из файла; при неудаче записи/обрыве можно повторить очистку. История с GPS/HR остаётся в V2. Неподтверждённые или несовпадающие FIT-пакеты не удаляются.
- Перед каждым обычным обновлением коллектор также освобождает подтверждённые пакеты и учитывает квитанции при поиске Garmin, поэтому уже импортированный ID не скачивается заново.
- Лимиты200пакетов/30MiB остаются предохранителем одной временной партии. Заполнение теперь завершает партию успешно: приложение может забрать накопленное, подтвердить и освободить место. Пакет, не поместившийся в файл, не помечается полученным и не теряется.
- scanOffset сохраняет продолжение поиска после обработанной страницы, максимум20страниц за запуск с прежним deadline. По достижении конца следующая сверка начинается с cutoff снова. История свыше1000Garmin-сводок больше не запирает поиск на первой тысяче. Это циклическое сканирование с ограниченным объёмом работы за открытие, не постоянный опрос.
- Если серверная БД недоступна, обслуживание не удаляет исходники. До применения новой миграции отсутствие таблицы квитанций означает пустой набор подтверждений: прежняя очередь сохраняется.
