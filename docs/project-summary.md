## Общая схема

PACE — Flutter-приложение для записи и хранения тренировок со специализациями, XP, достижениями и рекордами. Сервер — PocketBase 0.41.1 на домашнем Windows-ПК. Отдельного собственного сервера на Node.js/Python сейчас нет: используются PocketBase, его встроенная база SQLite, JavaScript-миграции и обработчики API.

Приложение → локальное хранилище и очередь отправки → HTTP API PocketBase → база аккаунтов и снимков прогресса. Тренировка сначала сохраняется локально; сеть не должна блокировать её завершение. Расчёт XP/достижений/рекордов и объединение истории выполняет Flutter-клиент. Сервер проверяет авторизацию, базовый формат данных и ревизию, сохраняет изменения в транзакции. Независимый серверный расчёт наград и защита от намеренной подмены собственного результата пока не реализованы.

## Клиент

Стек: Flutter/Dart; текущая среда Flutter stable 3.47.9, ограничение Dart в pubspec — ^3.13.5. Основные зависимости: geolocator (GPS), shared_preferences (локальные данные), flutter_secure_storage (сессия), http (API), crypto (стабильные идентификаторы).

Первый вход: четыре карточки о проекте → отдельные вход/регистрация → выбор персонажа при регистрации → приложение. Действующая сохранённая сессия восстанавливается; демонстрационный аккаунт по умолчанию не подставляется.

Работают GPS-запись с паузой и восстановлением черновика, история и подробный результат тренировки, профиль/специализация, XP и шкала уровней, 311 обычных достижений в 10 категориях и 67 рекордных дистанций (рекорды — 11-я категория медальонов). Первый GPS-результат дистанции даёт 50 XP, каждое строгое улучшение — 100 XP без ограничения числа улучшений. Уровень общий для видов спорта и вычисляется из XP; после 10-го шкала продолжается. Для рекордов нужны подходящие непрерывные GPS-данные; одна общая дистанция/длительность не заменяет время конкретного отрезка.

## Что где хранится

| Данные | Хранение |
| --- | --- |
| Email, учётные данные, имя | Коллекция PocketBase `pace_users`; пароль обрабатывает PocketBase, приложение его не сохраняет |
| Город, описание, параметры, специализация/персонаж | JSON-поле `profile` аккаунта на сервере |
| История с маршрутами, общий XP, достижения и рекорды | Локальный кэш аккаунта; серверный снимок в `pace_progress` после успешной синхронизации |
| Ещё не отправленные тренировки | Локальная очередь `_sync` |
| Активная незавершённая тренировка | Локальный черновик аккаунта; между устройствами не переносится |
| Спорт по умолчанию | Локальная настройка аккаунта на конкретном устройстве |
| Токен сессии | flutter_secure_storage, привязан к адресу сервера; web использует браузерную реализацию плагина |

Ключ прогресса включает адрес сервера и ID пользователя: `pace_progress_v2:<encoded server|accountId>`, черновик — тот же ключ с `:draft`. Смена аккаунта пересоздаёт защищённое дерево приложения; поздний ответ предыдущей сессии не принимается. Старая локальная история переносится с закреплением владельца, а не выдаётся каждому входящему аккаунту. Старые ключи сохраняются как резерв.

## Сервер

| Путь | Назначение |
| --- | --- |
| `server/runtime/pocketbase.exe` | Исполняемый файл PocketBase, вне Git |
| `server/pb_data/` | Рабочая база и серверные данные/секреты, вне Git |
| `server/pb_migrations/` | Версионируемые изменения коллекций: аккаунты → профиль → прогресс |
| `server/pb_hooks/` | Защищённые маршруты синхронизации |
| `server/start.ps1` | Проверка версии 0.41.1 и запуск с явными путями базы, миграций и hooks |
| `server/test.ps1` | Проверка на отдельном временном сервере/базе |

Коллекции:

- `pace_users`: аккаунты email/пароль, имя, профиль. Участник имеет доступ только к своей записи; изменение статуса подтверждения, чужие аккаунты и удаление через обычный клиент закрыты. Минимум пароля — 12 символов.
- `pace_progress`: одна запись на аккаунт. Поля: уникальный `owner`, числовая `revision`, JSON `snapshot`. Полная история пока хранится единым снимком, а не отдельными записями каждой тренировки. Обычный CRUD коллекции закрыт; используются собственные авторизованные маршруты.

Синхронизация:

1. Завершение тренировки атомарно сохраняет её локально вместе с наградами, балансом и очередью отправки. `sessionId` защищает от повторного сохранения.
2. `GET /api/pace/progress` получает снимок и его ревизию.
3. Клиент добавляет неизвестные сессии, устраняет повторные награды и объединяет прогресс. Локально начисленная награда может измениться после объединения с уже принятыми тренировками другого устройства.
4. `PUT /api/pace/progress` отправляет снимок с ожидаемой ревизией. Сервер проверяет владельца по токену, совпадение ревизии и сохранение ранее известных ID; затем повышает ревизию в транзакции.
5. При конфликте 409 клиент перечитывает данные и повторяет объединение. Потерянный ответ или повтор отправки не должны дублировать XP. Очередь очищается после проверки подтверждения; при ошибке остаётся на устройстве.

Автосинхронизация вызывается при открытии/возврате в приложение и завершении тренировки; ручная — «Прогресс → Обновить». Снимок/запрос ограничены 32 MiB. Для больших историй и массового запуска потребуется отдельный этап масштабирования хранения GPS и загрузки истории.

## Запуск и адреса

Из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\server\start.ps1
```

Сервер слушает `127.0.0.1:8090`, административная панель — `http://127.0.0.1:8090/_/`, health — `http://127.0.0.1:8090/api/health`. Скрипт не открывает роутер и не публикует сервер в интернете. Если сервер уже запущен, сначала остановить его Ctrl+C в его окне. Перед обновлением рабочего сервера сделать закрытую резервную копию всей `server/pb_data` при остановленном PocketBase; после запуска применяются новые миграции и загружаются hooks.

Клиент для Android-эмулятора в debug обращается к `http://10.0.2.2:8090` — это адрес домашнего ПК со стороны эмулятора. Для web/desktop debug — `http://127.0.0.1:8090`. Запуск Android: `flutter run`. Web: `.\run-web.ps1` (Chrome, постоянный `localhost:5050`).

Другой адрес API задаётся через `--dart-define=PACE_API_URL=https://<адрес-сервера>`. Для release адрес обязательно задавать; незащищённый HTTP допускается клиентом только на известных локальных debug-адресах. Физический телефон не использует `10.0.2.2` как адрес ПК: для внешних устройств настроен публичный API https://bodya1-pc.tail3c1c24.ts.net через Funnel и защищённый Caddy; Tailscale на клиенте не требуется.

- Реализованы аккаунты, серверный профиль и код синхронизации прогресса. 11 ноября наличие pace_users/pace_progress и применённых миграций аккаунтов/профиля/прогресса подтверждено по метаданным рабочей базы. Защищённый hook /api/pace/progress без токена вернул 401. Полный пользовательский цикл синхронизации на рабочей базе этим переносом не проверялся; прежние интеграционные тесты использовали временную базу.
- Сервер размещён на домашнем ПК; сон/выключение или остановка процесса прерывают доступ. Настроены публичный HTTPS Funnel и две задачи PACE для запуска PocketBase/Caddy после входа пользователя в Windows. Облачного хостинга и гарантированного запуска до входа нет.
- Клубы, ивенты и полноценные функции сообщества — будущие этапы; текущие экраны/иллюстрации не означают готовый социальный backend.
- OAuth VK/Яндекс/Mail и SMTP не подключены. Нельзя обещать подтверждение почты и восстановление пароля письмом; альфа допускает вход без подтверждения адреса.
- Синхронизация не заменяет резервную копию серверной базы. База, runtime, токены, пароли и локальные сборки не должны попадать в Git.
- В сохраняемый этап после `3e8d0f131219733a64a16feb37bd8f6b7321c652` входят стартовые карточки с прозрачными иллюстрациями v2 и программным фоном (см. docs/onboarding-visuals.md), исправление Android-сборки (`kotlin.incremental=false` при проекте на D: и Pub-кэше на C:) и игнорирование `android/.kotlin/`.
