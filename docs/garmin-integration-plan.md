## Нужный доступ

Для многопользовательского PACE — Garmin Connect Developer Program / Starter Business. Personal API предназначен только для собственных данных одного пользователя и не заменяет многопользовательскую интеграцию. Публичная текущая схема Starter: Activity JSON/FIT, Push only, без исторической загрузки, ограниченное число подключённых пользователей. Enterprise расширяет возможности; переход не требуется заранее. Бесплатность/конкретные коммерческие условия Starter не подтверждены, проверить перед принятием условий. В актуальном FAQ допускаются индивидуальные разработчики и стартапы, обязательное наличие юрлица по этим страницам не установлено.

Основной запрос — Activity API для данных тренировок. FIT может содержать временные измерения пульса, если они записаны устройством. Среднее значение не заменяет временной ряд; конкретные поля/доставка и доступ к файлу в выданном Starter-проекте проверяются по документации портала и тестовой записи. Health API для сна/суточных показателей автоматически не запрашивать: для нынешней цели это избыточно. Training API отправляет структурированные тренировки, его название не означает нужный нам импорт истории.

## Серверная работа после доступа

1. OAuth2 и привязка Garmin-пользователя к PACE, разрыв связи/отзыв согласия.
2. Отдельные HTTPS-маршруты callback/приёма Push, с проверками по официальной документации. Нынешний Caddy allowlist их не пропускает; открывать только точные проверенные маршруты, не ослаблять закрытие админки.
3. Приватное серверное хранение токенов, очередь обработки/повторов, разбор JSON/FIT.
4. Уникальный идентификатор поставщика и тренировки: не дублировать историю и XP при повторной доставке. Отдельно решить совпадение Garmin-импорта с записью PACE.
5. Сохранять происхождение и временной пульс, проверять покрытие/пропуски; политику качества ещё согласовать.
6. Проверить импорты с пульсом/без пульса, дубликаты, отзыв доступа; применять правила соревновательного зачёта на сервере.

Публичный Funnel уже есть, но домашний ПК должен быть доступен для доставки; поведение повторных доставок уточнить по выданной документации. Исторические тренировки не обещать в Starter. При отсутствии пульса импорт остаётся в личной истории по обычным правилам, не входит в зачёт события с требованием пульса. Наличие данных от сервиса не является абсолютным доказательством подлинности исходной активности.

## Текущий этап: официальный Personal API

Подтверждён пользователем12ноября2026. Бизнес-форму заполнять/отправлять сейчас не нужно. Страница создания ключа: https://connect.garmin.com/app/settings/personalApiToken . Вход, принятие условий, создание ключа выполняются пользователем лично. Ключ показывается один раз, срок выбирается30/90/180дней либо1год. Personal API — только собственные данные, не общая кнопка подключения для тестировщиков.

Подготовлены server/garmin/set-personal-key.ps1 и test-personal-connection.ps1. Первый интерактивно читает ключ скрытым вводом и шифрует Windows DPAPI в D:/Applications/PACE/Runtime/Garmin/personal-api-key.dpapi, вне репозитория, с ограниченными ACL. Расшифровка требует того же Windows-пользователя/компьютера; копия файла не является переносимым ключом. Повторная запись поверх существующего ключа запрещена без отдельной ручной проверки.

Второй скрипт проверяет выдачу токена по официальному Personal API endpoint из FAQ, ничего не печатает из секретов/сырого ответа и не сохраняет токен. Тренировки не скачивает и XP не меняет. Токен по документации живёт24часа или до истечения ключа, refresh token отсутствует. Импорт активности/разборFIT/привязка к аккаунтуPACE ещё не реализованы. Конкретный personalSwagger доступен черезJS; схему активности до импорта нужно изучить отдельно.

Пользовательский порядок: создать Personal API key → запустить .\server\garmin\set-personal-key.ps1 из проекта → сообщить только «ключ сохранён» → проверить test-personal-connection.ps1. Секрет в чат/исходники/Flutter dart-define не помещать. Автозапуск и серверные HTTPS-маршруты не менялись. Скрипты проверены синтаксически, реальные запросы не выполнялись, так как ключ ещё не предоставлен локально.


## Личная авторизация подтверждена — 12 ноября2026

Пользователь сам создал/сохранил Personal API key локально. test-personal-connection.ps1 завершился кодом0 с GARMIN_PERSONAL_AUTH_OK: официальный Garmin endpoint вернул успешный HTTP-статус и токен. Ключ/токен/тело ответа не выводились, токен не сохранялся, активности не скачивались и не импортировались. Это подтверждает только выдачу токена, не полную интеграцию или получение пульса.

Диагностика: исходный Invoke-RestMethod в WindowsPowerShell5.1 дал HTTP=none/Timeout, отдельный HttpClient также не получил ответа. Анонимный системный curl к тому же endpoint проходилTLS: GET404, POST400. Проверка переведена на штатный Windows curl с параметрами через приватный stdin pipe (ключ отсутствует в argv, временных файлах и логах), фиксированным официальным URL, обычной проверкой сертификата, без следованияredirect и тайм-аутами. Системные прокси/VPN/Firewall не менялись.

Garmin Personal endpoint фактически вернул токен напрямую в JWT-подобном формате, поэтому проверка теперь поддерживает прямой JWT и OAuthJSON, не печатая данные. ПодписьJWT отдельно не проверялась: проверена именно успешная выдача поHTTPS. Для полноценного импорта ещё нужны документированные resource endpoints, проверка авторизованного чтения активности, история/пульс, привязка владельцаPACE и дедупликация.
