# Регистрация и вход по почте

После стартовых карточек доступны отдельные кнопки **Регистрация** и **Войти**. Имя необязательно (до 40 символов), нужен email и пароль от 12 символов с повторным вводом. После регистрации выполняется вход и открывается выбор персонажа. Вход в существующий аккаунт возвращает сразу в профиль. Кнопка «Выйти» расположена внизу списка настроек.

Создаётся обычная запись коллекции `pace_users`. Учётная запись администратора используется только в панели PocketBase, не в приложении. Подтверждение email, восстановление пароля письмом и VK/Яндекс/Mail пока не подключены. Не использовать важный пароль от других сервисов в локальной тестовой среде.

## Локальный Android-эмулятор

Оставить сервер запущенным в своём PowerShell:

```powershell
cd D:\Developments\sport_platform
powershell -ExecutionPolicy Bypass -File .\server\start.ps1
```

В другом окне запустить приложение:

```powershell
cd D:\Developments\sport_platform
flutter pub get
flutter devices
flutter run -d emulator-5554
```

Идентификатор устройства нужно брать из `flutter devices`. В debug-сборке на Android адрес по умолчанию — `http://10.0.2.2:8090`: это доступ к компьютеру из стандартного Android-эмулятора. Для браузера и desktop в debug используется `http://127.0.0.1:8090`. На физическом телефоне эти адреса не подходят.

Для другого сервера передать `--dart-define=PACE_API_URL=https://...`. В release адрес обязателен и должен быть HTTPS; приложение не отправит пароль по обычному HTTP. В debug HTTP разрешён только для локальных адресов. Android debug network config разрешает незашифрованные запросы только к `10.0.2.2`, `127.0.0.1`, `localhost`; это исключение не добавлено в release. Локальный сервер слушает только loopback; публичный туннель пока не настроен.

## Сессия и данные

- Пароль не сохраняется. Токен записывается через `flutter_secure_storage` в отдельный ключ `pace_account_session_v1` вместе с адресом сервера. Запись проверяется чтением перед показом успешного входа.
- Сессия восстанавливается при открытии профиля или экрана аккаунта через `auth-refresh`. Невалидная сессия удаляется; временная ошибка сети сохраняет токен и предлагает повторить проверку. При смене сервера старый токен ему не отправляется.
- После входа профиль показывает имя аккаунта. Изменение имени в редакторе профиля сохраняется на сервере и остаётся после повторного входа. Описание, город, личные параметры и персонаж теперь сохраняются в поле profile аккаунта на сервере; обновления полей объединяются с последней записью.
- Для сохранения персонажа нужно нажать кнопку «Выбрать: …» на экране специализации. Выход из аккаунта не удаляет сохранённый выбор. После входа персонаж восстанавливается из аккаунта, включая вход с другого браузерного адреса.
- На native-платформах используется защищённое хранилище ОС. Web-реализация плагина использует браузерный WebCrypto и требует HTTPS или localhost; она не защищает от выполнения постороннего JavaScript в том же origin. Публичное размещение web-приложения требует отдельной настройки безопасности.
- Выход удаляет только сессию PACE с устройства. Форматы `pace_local_data`, `pace_active_workout`, `pace_profile_data` не меняются. История и XP остаются локальными; профиль вошедшего пользователя хранится на сервере, профиль гостя — на устройстве.
- Автоматических повторов регистрации нет. Если сервер создал аккаунт, но следующий вход или сохранение сессии не удались, форма предлагает вход с теми же данными. При потере ответа самой регистрации также можно переключиться на вход.

## Проверки

```powershell
flutter analyze
flutter test
$env:PACE_POCKETBASE_EXE = "$PWD\server\runtime\pocketbase.exe"
flutter test test/account_api_integration_test.dart
```

Последняя команда запускает настоящий PocketBase на свободном локальном порту с отдельной временной базой, использует тестовый аккаунт, проверяет регистрацию/вход/refresh/выход и отсутствие анонимного доступа к аккаунтам, затем останавливает процесс и удаляет только свою временную папку. Рабочая `server/pb_data` не используется. Без переменной проверка API пропускается.

Сервисные и widget-тесты проверяют ошибки формы, повторное нажатие, переход к персонажу, сохранность XP, сбои хранилища, восстановление сессии и смену сервера. Нативную работу защищённого хранилища необходимо отдельно проверить на устройстве; успешные тесты с подставленным хранилищем её не доказывают.


При запуске без аккаунта после знакомства с PACE доступны отдельные кнопки «Регистрация» и «Войти», каждая открывает нужный режим формы. Успешный вход возвращает прямо в профиль; после регистрации остаётся выбор персонажа. В профиле вошедшего пользователя кнопка «Выйти» находится внизу списка, после спорта по умолчанию. Промежуточного экрана «Ты в PACE» нет.


## Профиль аккаунта и обновление сервера

Добавлена миграция `1794225600_account_profile.js`. Перед запуском обновлённого приложения остановить сервер через Ctrl+C в его окне и снова выполнить `server/start.ps1`: PocketBase применит миграцию при старте. Затем полностью перезапустить приложение и войти заново. До применения миграции сохранение профиля не будет считаться успешным, приложение предложит перезапустить сервер.

При первом открытии аккаунта без серверного профиля сохранившийся старый локальный профиль переносится на сервер. Метка владельца запрещает присвоить тот же старый профиль второму аккаунту. Уже заполненный серверный профиль имеет приоритет. Если прежнее хранилище браузера больше недоступно, старые описание и персонажа автоматически восстановить нельзя: их нужно сохранить ещё раз после обновления.

В гостевом режиме нет автоматически созданного аккаунта: имя по умолчанию «Гость», без демонстрационного описания. Новый прогресс начинается с 0 XP. Существующие локальные тренировки и XP не удаляются. Вход может автоматически восстановить только ранее сохранённую настоящую сессию.

Для web-разработки запускать из корня `powershell -ExecutionPolicy Bypass -File .\run-web.ps1` или `flutter run -d chrome --web-hostname=localhost --web-port=5050`. Адрес всегда один: http://localhost:5050. Смена порта создаёт другой origin и отдельное браузерное хранилище, включая тренировки и сессию; серверный профиль доступен после повторного входа. Не удалять старые данные браузера ради проверки.

Поле JSON и миграция опираются на официальные инструкции PocketBase: https://pocketbase.io/docs/js-migrations/ и https://pocketbase.io/docs/js-collections/ .


## Первый запуск и обязательный вход

Производственный корень PaceApp теперь открывает StartupFlow. При первом запуске без сессии видны четыре истории о проекте: запись/история тренировок, специализация, развитие через опыт и сообщество. Доступны свайп, «Дальше», «Начать» и «Пропустить». Завершение или пропуск сохраняется в `pace_welcome_completed_v1`; затем открывается вход/регистрация. Пропустить можно знакомство, но вход в основное приложение обязателен.

С действующей сохранённой сессией выполняется auth-refresh и сразу открывается главный экран. При ошибке сети показана повторная попытка без доступа к главному экрану; токен при временной ошибке не удаляется. Отклонённая сессия возвращает на вход. После выхода закрываются также вложенные страницы приложения; системная кнопка «Назад» не возвращает их и не позволяет обойти авторизацию. Карточки не повторяются после сохранённого завершения/пропуска.

Регистрация сохраняет прежний шаг выбора персонажа перед главным экраном; обычный вход ведёт сразу в приложение. В старых сценариях тестирования внутренние тренировки проверяются через TestPaceApp, который существует только в test/support и не используется производственным корнем. Отдельные startup_flow_test/widget_test проверяют настоящий входной маршрут.


Карточки знакомства оформлены как полноэкранные постеры с персонажами PACE. После первого просмотра их можно снова открыть через **Профиль → О PACE**; повторный просмотр не меняет аккаунт и возвращает в профиль по «Пропустить» или «Начать».


Тексты четырёх карточек утверждены пользователем. Иллюстрации: телефон с главным экраном, бегун/лыжник/велосипедистка, +400 XP и 4→5, экран сообщества. Файлы и финальные промпты: docs/onboarding-visuals.md. Клубы, события и достижения на иллюстрациях показывают согласованное направление продукта; их функциональность будет согласовываться отдельно.


## Серверный прогресс — 10 ноября 2026

К аккаунту подключены тренировки, XP, достижения и GPS-рекорды с локальной очередью отправки, защитой от дубликатов и конфликтов двух устройств. Старые утверждения об исключительно локальном прогрессе выше относятся к предыдущему этапу. Перенос и перезапуск сервера описаны в [account-progress.md](account-progress.md). Активный черновик и выбор спорта по умолчанию остаются на конкретном устройстве; прогресс другого аккаунта не подмешивается. При переходе на другой web-origin подтверждённая серверная история загрузится после входа, а неотправленные записи старого origin нужно сначала синхронизировать там.
