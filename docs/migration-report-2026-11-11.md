## Особенности выполнения

1. Штатный GUI Docker открыл настройку Disk image location, но нативный выбор папки через автоматизацию не принял ввод. Диалог отменён без Apply. Диски перенесены при полностью остановленном Docker с полным хэшированием и junction прежнего каталога. Поэтому интерфейс Docker может показывать прежний C:-путь, физические файлы уже на D:.
2. Первый запуск Docker превысил тайм-аут 60 секунд, затем штатно завершился; подтверждены working engine, все контейнеры и HTTP.
3. Последовательная сверка мелких файлов Flutter шла медленно, до переключения остановлен только собственный verifier и выполнена повторная полная параллельная сверка.
4. В Gradle встретились пути более 260 символов: файлы были скопированы, Python-проверка потребовала extended-length prefix. После исправления повторная полная сверка успешна. Системные настройки LongPathsEnabled не менялись.
5. Предупреждения Java/Kotlin/AGP/SDK XML сохранились, но сборка завершилась успешно; версии/сборочные настройки ради подавления предупреждений не менялись.

## Ограничения и дальнейшее использование

Открывать проект в Android Studio: D:/Applications/PACE/Project. Перезапустить открытые редакторы/терминалы для нового окружения. Старые ярлыки должны работать через ссылки совместимости. Не переносить/удалять junction без обновления зависимых путей.

Брандмауэр, Tailscale Serve/Funnel, VPN и Windows-задачи не перенастраивались. Публичный доступ к API ещё не включён. Автозапуск PocketBase при перезагрузке не добавлялся; текущий сервер запущен в фоне. Docker/Ubuntu используют прежние механизмы автозапуска; перезагрузка всего ПК не проверялась.

Три критических сбоя Windows 0x133, выявленные до переноса, остаются отдельной задачей. Перенос не является их исправлением. Содержимое minidump не читалось и никуда не отправлялось.

## Откат

Сначала остановить использующий компонент сервис. Для инструментов/проекта убрать только соответствующую junction, скопировать рабочую папку с D: на прежний путь и сверить файлы, восстановить пользовательские переменные/local.properties из закрытых копий. Данные на D: до успешной проверки не удалять.

Для Ubuntu предпочтителен обратный штатный WSL --move с остановленной Ubuntu; для Docker — офлайн-перенос с проверкой и восстановлением прежнего каталога вместо junction. Старые диски сохранены в Backups, но они отражают состояние до миграции: после появления новых данных не заменять ими текущие диски без отдельного решения.

Для PocketBase резервная копия лежит в Backups/PocketBase. Перед восстановлением остановить единственный процесс PocketBase, сохранить текущее pb_data отдельно и восстановить всю согласованную копию, не отдельный SQLite-файл. Рабочая база этим переносом не заменялась резервной.
