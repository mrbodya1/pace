Установить Git, Flutter, Android Studio/Android SDK. Проверить требования `pubspec.yaml` и `pubspec.lock`; на момент передачи Dart constraint `^3.13.5`, приложение `sport_platform`, версия `1.0.0+1`.

```powershell
git clone https://github.com/mrbodya1/pace.git sport_platform
cd sport_platform
flutter pub get
flutter doctor
flutter analyze
flutter test
flutter run
```

Если репозиторий уже скачан, использовать `git pull` вместо повторного clone. Не переносить `build`, `.dart_tool`, кэши Gradle и старый `android/local.properties` с путями старого ПК. Неопубликованные изменения сохранить отдельно до переноса.

Если сервер всё же был запущен пользователем после этой сводки, отдельно перенести его `pb_data` с остановленного сервера и `runtime/pocketbase.exe`. База, пароли и ключи не находятся в GitHub. Не создавать новую базу поверх старой без резервной копии.

## Согласованная система XP — уже подключена

Любой персонаж занимается любым спортом. База определяется видом тренировки, бонус — выбранной при старте специализацией. Четыре компонента считаются независимо, итог округляется один раз. Старые тренировки и баланс не пересчитываются.

Обозначения: D — км, T — активные часы без пауз, H — набор высоты в метрах. Опорная дистанция R за час:

| Спорт | R |
| --- | --- |
| Бег / трейл | 10 км |
| Ходьба | 5 км |
| Лыжи / роллеры | 15 км |
| Велосипед | 30 км |
| Плавание | 2 км |

- Дистанция: `100 × D / R`.
- Темп/скорость: `100 × (D / T) / R`, если D и T положительные, иначе 0. Более быстрая тренировка даёт больше XP за этот компонент.
- Длительность: `100 × T`.
- Подъём: `H`, кроме плавания — там всегда 100 XP у всех персонажей.
- Итог: `round(сумма компонентов × (1 + бонус))`.

Бонусы:

- Универсальный класс `multiathlete`: +5% к любому виду.
- Бегун: +20% за бег и трейл.
- Лыжник: +20% за лыжи (не за роллеры).
- Велосипедист: +20% за велосипед.
- Пловец: +20% за плавание.
- Марафонец, только бег/трейл: `20% × D / 21`; 10 км ≈ 9,52%, 21 км = 20%, дальше растёт без потолка.
- Трейлраннер, только бег/трейл: `20% × H / 300`; 150 м = 10%, 300 м = 20%, дальше растёт без потолка.
- Без выбранной специализации — только база.

Пример: бег 10 км за активный час с 100 м подъёма = 400 базовых XP, у бегуна 480 XP. Плавание 2 км за час = 400 базовых XP, даже без измеренного подъёма.

Тренировка короче 50 м не добавляется в историю и не даёт XP. Плавательный темп отображается на 100 м.

`WorkoutXp` сохраняет версию 1, компоненты, общий итог, бонус и снимок специализации/пола в необязательном `xpBreakdown`. У `Workout` добавлены необязательные `elevationGain`, `startedAt`, `sessionId`; у RoutePoint — высота. Старые данные читаются без новых полей.

Набор высоты: `ElevationTracker`, порог изменения 3 м; после паузы сбрасывается опорная точка, чтобы не добавлять перепад через паузу.

## Фоновая запись — реализована, нужна проверка на устройствах

- `services/workout_location_settings.dart`: Android foreground service с постоянным уведомлением и WakeLock, точность best, интервал 1 с; iOS fitness, автоматическая пауза выключена, background location включён.

- Поток GPS отменяется последовательно, не стартует из фона. При сворачивании уже активный поток продолжается. На паузе/финише отменяется. Ошибка GPS ставит запись на паузу с ручным продолжением.
- Отдельного headless Flutter Engine и автоматического перезапуска после убийства процесса нет.
- Нативная сборка и реальная фоновая работа на Android/iOS помощником не проверены. Пользователь ранее успешно запускал приложение на Android-эмуляторе.

- `LocalStorageService`: последовательная очередь операций. `completeWorkout` перечитывает актуальную историю, сохраняет баланс+историю одной JSON-записью, затем чистит черновик.
- Документы в репозитории: `docs/background-recording.md`, `docs/workout-recovery.md`.

## Будущие продуктовые задачи

- Сообщество с разделами «Друзья / Клуб / Соревнования». Пока это честные заготовки без настоящего backend и выдуманных результатов.
- Участники видят доступные соревнования, организаторы клубов создают их.
- Только автоматическое попадание подходящих тренировок в соревнования. Неподходящие просто не включаются; никаких ручных внесений/вердиктов «зачтено/не зачтено».
- Организатор выбирает только предусмотренные параметры: пол, спорт, километры, темп, длительность, набор высоты и другие реально собираемые показатели. Произвольных пользовательских условий нет.
- Пользователь хочет каденс в будущем. Не считать его уже собираемым. Не выдавать неопределённые/отсутствующие измерения за точные.
- Главную не перегружать: оставить уровень/баллы и аккуратные сводки; подробная история/статистика/достижения в «Прогрессе», социальные функции в «Сообществе».
- Профиль в перспективе: полноценные настройки, разрешения, синхронизация, внешние сервисы, рост/вес/возраст, кроссовки, пульсовые зоны. Не всё это уже реализовано.
- Карта маршрута, импорт внешних сервисов, реальное сообщество и соревнования ещё не готовы.
